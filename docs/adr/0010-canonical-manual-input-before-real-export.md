# ADR 0010 — Канонический ручной ввод до получения реальной выгрузки

**Статус:** Accepted  
**Дата:** 2026-07-13

## Контекст

Владельцы салонов могут не передавать финансовые выгрузки незнакомому исполнителю. Ожидание реального файла не должно блокировать проверку финансового ядра: уже существуют физическая спецификация и 45 контрольных наборов, при этом структура конкретной CRM неизвестна.

## Принятое решение

MVP начинается на канонических листах. Поддерживаются ручной ввод, вставка подготовленных данных и CSV, уже приведённый к каноническому контракту. Финансовое ядро отделено от source-specific импорта; реальная выгрузка потребуется позднее для адаптера конкретного источника.

## Рассмотренные альтернативы

1. Полностью блокировать разработку до получения файла.
2. Придумать универсальный CRM-импорт без реальных данных.
3. Начать с интеграции с одной предполагаемой системой.
4. Начать с канонического ручного контракта.

## Последствия

Положительные: можно реализовывать и тестировать расчёты, снижается зависимость от доступа к данным клиента, сохраняется независимость от CRM, первый пилот может вводить данные локально.

Ограничения: ручная подготовка данных, отсутствие автоматического обновления и подтверждённого mapping внешнего источника, возможная доработка колонок после первого пилота.

## Условия пересмотра

- получена реальная обезличенная выгрузка;
- выбран первый источник;
- подтверждены внешний ID и line ID;
- появляется потребность в регулярном автоматическом импорте.
